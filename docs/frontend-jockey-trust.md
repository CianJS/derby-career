# 기수 신뢰도 Frontend: 현재 계약에서 가능한 연결과 남은 작업

기준 develop: `307876b` (2026-10-16 확인). 신뢰도 전체 기능 완료가 아닌 **기존 서버 관계값 조회 연결과 고정 수치 제거** 범위다. Backend의 새 신뢰도 PR/계약이 이 기준에 없으므로 계산·응답 필드·API를 가정하지 않는다.

## 연결한 데이터와 화면

- 기존 `GET /v1/careers/{careerId}/race-entries`의 `jockeys[].chemistry`는 해당 소유자의 말–기수 관계 테이블에서 읽은 값이다. 기존 ServerSaveController가 생성 검증기로 확인하고 현재 workspace의 Career ID/revision과 대조한 응답을 재사용한다. 새로운 HTTP 경로/쓰기 명령은 없다.
- `lib/career/jockey-trust.ts`는 이 값을 표시용으로 읽는다. 현재 Career·보유 말·revision이 맞지 않거나 저장/재확인 중·조회 실패이면 과거 숫자를 표시하지 않는다. 0은 유효한 숫자로 표시하며 미조회·미지원·로딩과 다르다. 범위 밖의 숫자는 보정하지 않고 정보 없음으로 처리한다.
- 기수 목록과 상세는 같은 조회 함수/표시 컴포넌트를 사용하며 말 이름을 함께 표시한다. 관계값을 기수 공통 능력치와 분리했다. 출전 화면의 기수 카드와 선택 요약도 동일한 값을 사용한다. 기존 추천·수동 선택·출전 잠금 정책은 유지한다.
- 현재 Local Career에는 관계 저장값이 없다. 기수 카탈로그의 상수 0이나 과거 출전 Snapshot을 현재 신뢰도로 사용하지 않는다. Local 화면은 정보 없음이며, 저장소를 별도로 만들거나 이관하지 않는다.
- 은퇴 Snapshot에도 보존된 신뢰도가 없다. 현역 기수 카탈로그에서 숫자를 복사하던 표시를 제거하고 해당 기록의 신뢰도 정보 없음으로 표시한다.
- 경주 결과에는 기수 이름과 신뢰도 변화 정보 없음을 표시한다. 확정 변화가 없는 상황에서 `변화 없음` 또는 임의 증감값을 보여주지 않는다. 관전/결과 재진입에 쓰기나 계산을 추가하지 않았다.
- 현재 이벤트 계약에는 신뢰도 효과/확정 변화가 없다. 기존 월간 이벤트 UI는 유지하며 가짜 신뢰도 변화량을 추가하지 않는다.

## Backend / 총괄에게 요청할 계약

아래는 필요한 데이터의 의미이며, 아직 존재하지 않는 필드명/경로를 구현한 것이 아니다. Backend의 확정 OpenAPI·공유 도메인과 생성 검증기가 통합되면 후속 연동한다.

1. **공유 Career의 말별 관계 저장값**: 기수 ID와 0~100 신뢰도, 새 육성마 초기화 및 기존 저장의 명시적인 이전 규칙. Local/Server가 같은 공유 계산을 사용해야 하므로 Frontend에서 별도 증가·감소·초기값 규칙을 만들지 않는다. 자유 기수 등 응답에 없는 관계를 0으로 해석할지 미조회로 볼지도 계약에 명시해야 한다.
2. **확정된 경주별 변화**: 대상 말/기수 ID, 이전값·이후값·확정 증감량, RaceRun/기록 ID. 완료 응답뿐 아니라 저장된 RaceRun/완료 기록 재조회로 복원할 수 있어야 한다. 변화 없음과 오래된 기록의 정보 없음이 구별되어야 한다. 기존 Journal의 동일 UUID/본문 재확인과 다른 완료 UUID에 대해서도 1회 적용되어야 한다. Simulation Log를 읽어 Frontend에서 변화를 다시 계산하지 않는다.
3. **확정된 이벤트 변화**: 기존 이벤트 결과/이력에 대상 기수와 이전·이후값·증감량, 실제 적용 여부가 필요하다. 선택 전 예상 효과와 저장된 결과를 분리하고, 신뢰도 효과가 없는 이벤트에는 증감을 표시하지 않는다. 기존 선택 명령의 멱등성과 결과 재접속 복원을 유지해야 한다.
4. **은퇴 당시 관계 보존**: 은퇴 Snapshot과 Local Archive에 해당 말의 확정 신뢰도를 보존할 공유 타입/검증/투영 경로가 필요하다. 같은 말 정의로 새 육성을 시작해도 이전 은퇴마의 값을 읽거나 덮어쓰면 안 된다.
5. **명칭/계약 정리**: 사용자 화면은 신뢰도로 변경했지만 내부 `chemistry`는 현행 계약과 호환되게 유지했다. 새 서버 계약의 최종 명칭과 범위·누락값 의미를 알려주면 기존 조회 경계를 교체한다.

## 검증 범위와 제한

- 일반 테스트: 실제 App DOM에서 서버 목록/상세/기수 선택/출전 요약 값 일치, 새로 마운트한 앱에서 복원, 조회 오류 시 이전 숫자 숨김과 재조회, Local Save에 서버 데이터가 기록되지 않음을 검사한다. 경계 테스트는 0/100·미조회·범위 오류·Career/revision 변경·모드 전환을 검사한다.
- 별도 통합 테스트: 실제 Fastify·생성 검증기·PGlite PostgreSQL 엔진에서 관계값 조회/재접속/실패/복구, 소유자 차단, 은퇴 후 새 말의 독립 관계를 확인한다. SQL의 72는 격리 테스트 데이터이며 제품의 계산식이나 Mock API가 아니다.
- Playwright: 390×844 / 1440×900, 라이트/다크에서 Local의 미지원 표시, 목록/상세/은퇴/출전/결과 레이아웃과 저장 재접속, 결과 재진입 시 기록 미변경을 검사한다. 기존 경주 관전·저장·카탈로그 E2E도 유지한다.
- 실제 서버 화면은 App DOM 테스트 및 실제 API/DB 통합 테스트로 나눠 검증한다. 운영 빌드는 개발 세션 bridge를 404로 닫기 때문에 이 Playwright 흐름을 서버 로그인/운영 서버 브라우저 검증으로 주장하지 않는다.
- **미완료**: Local 실제 신뢰도 저장·성장, 경주 증가/감소/변화 없음 확정 표시, 이벤트 신뢰도 결과, 은퇴 당시 숫자 보존. 위 계약이 없어 아직 구현·검증할 수 없다.
- Issue #25의 경주 정보 QA, 공유 계산·DB·API·계약·이벤트 콘텐츠 및 로그인은 변경하지 않는다. PR만 제출하고 병합·Site 배포는 하지 않는다.
